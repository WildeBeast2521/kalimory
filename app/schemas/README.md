# Room schemas

This directory holds the exported Room schema JSON for `AppDatabase`, one file per database version:

    io.github.gonbei774.calisthenicsmemory.data.AppDatabase/<version>.json

The files are inputs to `MigrationTestHelper` (the `androidTest` source set adds this directory to its assets) and are the evidence behind the supported-version policy in `docs/development/supported-database-versions.md`.

## Rules

- Never hand-edit a schema file. Every file is produced by the Room compiler from the entities of the commit listed below.
- A committed schema is immutable. If the entities change, bump the database version, add a migration, and commit the new version's schema alongside the existing ones.
- Only the current version's file is generated by the build (`room.schemaLocation` in `app/build.gradle.kts`). Historical files are recovered once from their own commits and never regenerated from current sources.

## Checking and adding schemas

`scripts/check-room-schemas.sh` regenerates the current schema with `./gradlew :app:kspDebugKotlin --rerun` and fails when:

- generation changes any committed schema or adds a schema file;
- a file's name is not a version, is newer than the current version, or disagrees with its `database.version`;
- a file lacks an identity hash or entities, or contains an absolute local path;
- the current schema's identity hash differs from the generated `AppDatabase_Impl`.

With `SCHEMA_BASE_REF=<ref>`, it also fails when a schema committed at that ref was modified, deleted, renamed, or changed in type. CI runs the script with the pull-request base (or the previous push) as the reference.

After a database version bump:

1. Run `./gradlew :app:kspDebugKotlin` to generate the new `<version>.json`.
2. Commit the new file.
3. Run `scripts/check-room-schemas.sh`. It fails while the new file is uncommitted.
